# Multi-Service Cloud Deployment with Docker Swarm on Microsoft Azure

A distributed microservices infrastructure deploying 4 polyglot applications (**Go**, **Node.js**, **Next.js**, and **Laravel**) across a 3-node **Docker Swarm Cluster** hosted on **Microsoft Azure Virtual Machines**.

---

## 🏗️ Cloud & Cluster Architecture

This project runs on **3x Linux Virtual Machines** deployed on Microsoft Azure, connected via Azure Virtual Network (VNet) and VNet Peering:

* **1x Master VM (`Docker-Master`)**: Acts as the Docker Swarm Manager/Leader node. It orchestrates container scheduling, maintains cluster state, and routes incoming traffic across the overlay network.
* **2x Worker VMs (`Docker-Worker1` & `Docker-Worker2`)**: Act as Docker Swarm Worker nodes that pull container images and execute the distributed service replicas across the cluster.

```text
                      +-----------------------+
                      |     Docker-Master     |
                      |   (1x Manager Node)   |
                      +-----------+-----------+
                                  |
              +-------------------+-------------------+
              |         Azure VNet / Peering          |
+-------------v-------------+           +-------------v-------------+
|      Docker-Worker1       |           |      Docker-Worker2       |
|      (Worker Node 1)      |           |      (Worker Node 2)      |
+---------------------------+           +---------------------------+
```

## 🚀 Quick Start (Docker Compose)

To clone and run all 4 applications locally or on a single host:

```bash
# 1. Clone the repository
git clone https://github.com/<YOUR-USERNAME>/<YOUR-REPO-NAME>.git
cd <YOUR-REPO-NAME>

# 2. Build and start all 4 containers
docker compose up -d --build
```

## 🌐 Deploying to the Azure Docker Swarm Cluster

### 1. Initialize Swarm on the Master VM
```bash
docker swarm init --advertise-addr <MASTER-PRIVATE-IP>
```

### 2. Join the 2x Worker VMs to the Cluster
Run the join command generated by the master node on both **Worker 1** and **Worker 2**:
```bash
docker swarm join --token <SWARM-WORKER-TOKEN> <MASTER-PRIVATE-IP>:2377
```

Verify all 3 VMs are active from the Master node:
```bash
docker node ls
```

### 3. Deploy the Application Stack
```bash
# Deploy the services across the 3-node cluster
docker stack deploy -c docker-compose.yml my_apps

# Verify running containers across Master, Worker1, and Worker2
docker stack ps my_apps --filter "desired-state=running"
```

## 🔧 Troubleshooting Laravel Error (After Pulling Repo)

If you pull this repository, start the containers, and see a **`500 Internal Server Error`**, **`MissingAppKeyException`**, or **`SQLSTATE[HY000]: General error: 1 no such table: sessions`** on the Laravel application (`http://localhost:8000`), run this single command in your terminal to automatically copy `.env`, generate the `APP_KEY`, run SQLite migrations, and clear the cache:

```bash
docker compose exec laravel-app sh -c "cp -n .env.example .env && php artisan key:generate --force && php artisan migrate --force && php artisan config:clear"
```
